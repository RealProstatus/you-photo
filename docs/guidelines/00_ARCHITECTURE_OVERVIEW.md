# 00. Общий архитектурный гайдлайн проекта «YouPhoto»

Данный документ является мастер-спецификацией для всех агентов и разработчиков проекта **«YouPhoto»**. Все модули обязаны строго следовать контрактам, перечисленным ниже, и UML-диаграммам из `C:\Users\notebook\UNN\Архитектуры`.

---

## 1. Ключевые архитектурные инварианты и ограничения

1. **Язык интерфейса (`S-USE-01`)**: Весь пользовательский интерфейс (веб-шаблоны, окна PySide6, сообщения об ошибках валидации, уведомления Telegram, названия статусов) должен быть **строго на русском языке**.
2. **Разделение ролей (`S-SEC-03`, `U-C-01`, `U-M-01`, `U-A-01`)**:
   - `CLIENT` («Клиент»): создается через публичную регистрацию на сайте (`US-08`). Имеет доступ только к веб-приложению и только к своим заказам.
   - `MANAGER` («Менеджер»): создается только Администратором (`U-A-03`), привязан к одному конкретному салону (`salon_id`). Работает в десктопном приложении, видит заказы только своего салона (где его салон — `assigned_salon` или `pickup_salon`), редактирует оборудование/услуги только своего салона (`U-M-07`).
   - `ADMIN` («Администратор»): создается Администратором или суперпользователем. Видит заказы всех салонов (`U-A-06`), управляет справочниками всех салонов (`U-A-02`, `U-A-04`), сотрудниками (`U-A-03`) и может вручную переназначать салон-исполнитель (`U-A-05`).
3. **Заказы без учетной записи клиента (`US-07`)**:
   - Заказ «Фото на документы» (`OrderType.IN_SALON`) создается менеджером в десктопном приложении **без привязки к клиенту** (`client = None`), сразу назначается текущему салону менеджера (`assigned_salon = pickup_salon = current_salon`), минуя алгоритм автораспределения (`US-02`), и сразу получает статус `PRINTING` («В печати»).
4. **Машина состояний заказа (10 статусов, п. 5.2 Функциональной спецификации)**:
   Любой переход статуса вне разрешенного графа должен отклоняться с ошибкой `InvalidStatusTransitionError` не позднее чем за 2 секунды (`U-M-03`, `S-PERF-01`).
5. **Актуальность статусов (`S-PERF-03`, `U-C-07`, `U-M-02`)**:
   Веб-клиент (`StatusPollerJS`) и Десктопный клиент (`OrderQueuePresenter`) опрашивают сервер каждые **5 секунд**, обеспечивая отображение нового статуса не позднее чем через **10 секунд**.
6. **Хранение и валидация файлов (`S-INT-01`, `S-SEC-04`)**:
   - Допустимые форматы: `JPEG`, `PNG`, `HEIC`, `TIFF`.
   - Максимальный размер одного файла: **50 МБ включительно** (`50 * 1024 * 1024` байт).
   - Срок хранения исходных файлов: **30 календарных дней** с момента перехода заказа в статус `COMPLETED` («Завершен»), после чего файлы удаляются фоновой задачей (`RetentionCleanupJob`), но карточка заказа и история статусов сохраняются.

## 2. Единые перечисления (Enums)

Все модули (`backend` и `desktop`) используют единые коды перечислений:

### 2.1. Роли пользователей (`UserRole`)
- `CLIENT` — Клиент
- `MANAGER` — Менеджер
- `ADMIN` — Администратор

### 2.2. Тип заказа (`OrderType`)
- `ONLINE` — Онлайн-заказ (из веб-приложения, `US-01`)
- `IN_SALON` — В салоне («Фото на документы», `US-07`)

### 2.3. Статусы заказа (`OrderStatus`)
| Код (`Enum`) | Русское название в UI | Описание |
|--------------|-----------------------|----------|
| `NEW` | Новый | Создан клиентом, ожидает запуска автораспределения |
| `PENDING_ROUTING` | Ожидает распределения | Автораспределение не нашло салон или заказ возвращен из-за поломки (`US-02 1a`, `US-03 1a`) |
| `ASSIGNED_TO_SALON` | Передан в салон | Назначен салон-исполнитель (`US-02`) |
| `IN_PROGRESS` | В работе | Принят менеджером салона-исполнителя (`US-03`) |
| `PRINTING` | В печати | На этапе печати (или стартовый статус для `US-07`) |
| `FINISHING` | Оформление | На этапе постпечатного оформления (багет, люверсы, ламинация) |
| `NEEDS_CLARIFICATION` | Требует уточнения | Брак, плохой исходник или повреждение при доставке (`US-03 2a`, `US-06 2a/7a`) |
| `IN_TRANSIT` | Передается в салон выдачи | Готов в салоне-исполнителе, отправлен в другой салон выдачи (`US-03`, `US-06`) |
| `READY_FOR_PICKUP` | Готов к выдаче | Находится в салоне выдачи, ожидает клиента (`US-03`, `US-06`, `US-07`) |
| `COMPLETED` | Завершен | Оплачен и выдан клиенту (конечный статус) |

### 2.4. Стандарты документов (`DocumentStandard`)
- `RF_PASSPORT_35x45` — Паспорт РФ (35×45 мм)
- `FOREIGN_PASSPORT_35x45` — Загранпаспорт (35×45 мм)
- `SCHENGEN_VISA_35x45` — Виза Шенген (35×45 мм)
- `US_VISA_50x50` — Виза США (50×50 мм)

## 3. Таблица допустимых переходов статусов заказа

Реализуется в методе `Order.can_transition_to(next_status, actor)` в `backend/apps/core/`:

| Исходный статус | Новый статус | Кто выполняет переход | Условие |
|-----------------|--------------|-----------------------|---------|
| `NEW` | `ASSIGNED_TO_SALON` | Система (`RoutingService`) | Найден подходящий салон |
| `NEW` | `PENDING_ROUTING` | Система (`RoutingService`) | Подходящий салон не найден (`US-02 1a`) |
| `PENDING_ROUTING` | `ASSIGNED_TO_SALON` | `ADMIN` (или `RoutingService`) | Вручную выбран салон с нужным оборудованием и услугами |
| `ASSIGNED_TO_SALON` | `IN_PROGRESS` | `MANAGER` (исполнитель) / `ADMIN` | Принятие заказа в работу |
| `ASSIGNED_TO_SALON` | `ASSIGNED_TO_SALON` | `ADMIN` | Ручное переназначение другого салона (`US-02 3a`) |
| `IN_PROGRESS` | `PRINTING`, `FINISHING` | `MANAGER` (исполнитель) / `ADMIN` | Ход выполнения заказа |
| `IN_PROGRESS` | `PENDING_ROUTING` | `MANAGER` (исполнитель) / `ADMIN` | Поломка оборудования (`US-03 1a`) |
| `PRINTING` | `FINISHING` | `MANAGER` (исполнитель) / `ADMIN` | Переход от печати к оформлению |
| `PRINTING`, `FINISHING` | `READY_FOR_PICKUP` | `MANAGER` (исполнитель) / `ADMIN` | Заказ готов И `assigned_salon == pickup_salon` |
| `PRINTING`, `FINISHING` | `IN_TRANSIT` | `MANAGER` (исполнитель) / `ADMIN` | Заказ готов И `assigned_salon != pickup_salon` |
| `IN_TRANSIT` | `READY_FOR_PICKUP` | `MANAGER` (салон выдачи) / `ADMIN` | Заказ получен в пункте выдачи (`US-06`) |
| `READY_FOR_PICKUP` | `COMPLETED` | `MANAGER` (салон выдачи) / `ADMIN` | Только после проверки `pickup_code` и оплаты (`US-06`, `US-07`) |
| `IN_PROGRESS`, `PRINTING`, `FINISHING`, `IN_TRANSIT`, `READY_FOR_PICKUP` | `NEEDS_CLARIFICATION` | `MANAGER` / `ADMIN` | Плохое фото, повреждение при доставке или брак при выдаче |
| `NEEDS_CLARIFICATION` | `IN_PROGRESS` | `MANAGER` / `ADMIN` / `CLIENT` (после загрузки нового фото или согласия) | Возврат в работу после уточнения |

*Примечание:* Статус `COMPLETED` является терминальным — из него переходы запрещены.

## 4. Контракты межмодульных интерфейсов (`system_overview.puml`)

1. **`IBackendApi`** — реализуется на стороне сервера в `OrderService` и экспортируется через REST API (`/api/v1/...`), а на стороне десктопного клиента оборачивается адаптером `RestApiClient`.
2. **`IFileStorage`** — реализуется в `backend/apps/storage/services.py` (`MinioFileStorage` с поддержкой локального S3/MinIO и fallback на файловое хранилище в тестах).
3. **`INotificationService`** — реализуется в `backend/apps/notifications/services.py` (`AppriseNotificationService`).
4. **`ICameraService`** и **`IPrinterService`** — реализуются в `desktop/hardware/` (`UsbCameraService`, `WindowsPrinterService`) с поддержкой как реальных вызовов Windows (WIA/MTP, `QtPrintSupport`/`win32print`), так и режима стендовой эмуляции (`YOUPHOTO_HARDWARE_MOCK=True`) для автотестов.
