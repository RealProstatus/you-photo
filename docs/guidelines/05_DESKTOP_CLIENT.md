## 2. Архитектурный паттерн MVP (`desktop_client_module.puml`)

Десктопное приложение строится по паттерну **Model-View-Presenter (MVP)** на `PySide6`, чтобы вся логика презентеров легко тестировалась через `pytest` и `pytest-qt` без зависания модальных окон.

### 2.1. `RestApiClient` (`desktop/api_client/rest_client.py`)
Реализует интерфейс `IBackendApi`:
- Хранит `base_url` и `auth_token` (или сессию) текущего авторизованного сотрудника, а также профиль (`user_id`, `role`, `salon_id`).
- Методы:
  - `login(login: str, password: str) -> dict`
  - `list_orders(filters: dict = None) -> list[dict]`
  - `get_order(order_id: str) -> dict`
  - `create_document_order(payload: dict) -> dict`
  - `update_order_status(order_id: str, status: str, comment: str = "") -> dict`
  - `reassign_order(order_id: str, target_salon_id: str, comment: str = "") -> dict`
  - `complete_pickup(order_id: str, pickup_code: str) -> dict`
  - `download_photo(download_url: str, target_path: str) -> str`
  - `manage_salon_catalog(salon_id: str, data: dict) -> dict`
  - `list_salons()`, `create_salon()`, `update_salon()`, `delete_salon()`
  - `list_users()`, `create_user()`, `update_user()`

### 2.2. `MainWindow` (`desktop/views/main_window.py`)
- Хранит `current_salon_id` и роль текущего сотрудника (`MANAGER` или `ADMIN`).
- **Разграничение прав в UI (`U-M-01`, `U-A-01`, `S-SEC-03`)**:
  - Если вошел `CLIENT` — вход в десктопное приложение отклоняется («Доступ разрешен только сотрудникам салона»).
  - Если вошел `MANAGER`:
    - Видит очередь заказов **только своего салона** (`U-M-02`);
    - В разделе справочников может редактировать оборудование и услуги **только своего салона** (`U-M-07`); кнопки «Все салоны», «Добавить салон», «Удалить салон», «Сотрудники» и «Назначить салон вручную» скрыты/недоступны (`U-M-01`).
  - Если вошел `ADMIN`:
    - Видит заказы **всех салонов** с фильтром по филиалу и статусу (`U-A-06`);
    - Может вручную назначать/переназначать салон-исполнитель (`U-A-05`);
    - Управляет списком салонов (добавление, скрытие, удаление, `U-A-02`), оборудованием и услугами всех салонов (`U-A-04`) и учетными записями сотрудников (`U-A-03`).
- Запускает `QTimer` с интервалом **5000 мс** (`5 секунд`) для автоматического обновления очереди заказов (`OrderQueuePresenter.refresh_queue()`), выполняя требование `U-M-02` и `S-PERF-03` (`≤ 10 с`).

### 2.3. `OrderQueuePresenter` (`desktop/presenters/order_queue_presenter.py`)
- `refresh_queue() -> list[dict]`: запрашивает список заказов через `RestApiClient`.
- `change_order_status(order_id, status, comment="")`:
  - Отправляет запрос смены статуса.
  - При переводе в `NEEDS_CLARIFICATION` требует обязательный комментарий для клиента (`US-03 2a`).
  - При возврате заказа из-за поломки оборудования (`US-03 1a`) переводит в `PENDING_ROUTING` для перераспределения.
  - При недопустимом переходе показывает русскоязычное пояснение от сервера (`U-M-03`).
- `download_order_photos(order_id, target_dir) -> list[str]` (`U-M-04`):
  - Скачивает исходные файлы фотографий заказа в выбранную папку рабочей станции.
- `print_order(order_id, printer_name) -> PrintResult` (`U-M-06`):
  - Скачивает фото во временную папку и отправляет задание в `IPrinterService.send_to_print(PrintJob(...))` с форматом и тиражом из позиции заказа.
  - При ошибке принтера показывает причину и оставляет возможность повторить печать (`US-07 8a`, `U-M-06`).
- `complete_pickup(order_id, pickup_code) -> bool` (`US-06`, `FUNC 5.2`):
  - Проверяет код выдачи через сервер. При неверном коде (`US-06 5a`) показывает ошибку, статус остается `READY_FOR_PICKUP`. При браке при получении (`US-06 7a`) позволяет перевести заказ в `NEEDS_CLARIFICATION`.

### 2.4. `DocumentPhotoPresenter` (`desktop/presenters/document_photo_presenter.py`)
Реализует сценарий `US-07` («Оформление заказа "Фото на документы" в салоне»):
1. Выбор стандарта документа (`DocumentStandard`: Паспорт РФ 35×45, Загранпаспорт 35×45, Виза Шенген 35×45, Виза США 50×50).
2. `import_from_camera()`:
   - Вызывает `ICameraService.import_latest_photo()`.
   - Если камера не подключена или снимок поврежден (`Исключение 3a`) — показывает ошибку, заказ не создается (`U-M-05`).
3. `apply_auto_crop(standard)` и ручная корректировка кадрирования по шаблону выбранного документа (с учетом п. 3 Функциональной спецификации: поддержка как автокадрирования, так и ручного кадрирования по рамке-шаблону, а также выгрузки/загрузки снимка после внешнего редактора `Исключение 5б`).
4. Расчет стоимости по количеству копий.
5. Если клиент отказывается до подтверждения (`Исключение 7a`) — удаляет временный снимок, заказ не создается.
6. `confirm_and_print(copies, printer_name)`:
   - Загружает откадрированный снимок на сервер и создает заказ без учетной записи клиента сразу на текущий салон в статусе `PRINTING` (`US-07 шаг 7`).
   - Отправляет снимок на выбранный принтер (`IPrinterService.send_to_print`). При ошибке принтера (`8a`) или браке отпечатка (`9a`) позволяет повторить печать.
   - По кнопке «Напечатано» переводит заказ в `READY_FOR_PICKUP`, а после оплаты и выдачи — в `COMPLETED` (либо оставляет `READY_FOR_PICKUP` с выдачей номера и кода клиенту, если клиент заберет позже по `Исключению 10a`).

### 2.5. `SalonAdminPresenter` (`desktop/presenters/salon_admin_presenter.py`)
Реализует сценарии `US-05` и ручное управление `US-02`:
- `update_equipment_and_services(salon_id, equipment_list, service_ids)`:
  - Проверяет корректность введенных данных (`Исключение 3a`).
  - Если у отключаемого оборудования или услуги есть активные заказы в работе (`Исключение 4a`), предупреждает пользователя и по подтверждению отправляет эти заказы на перераспределение (`US-02`).
- `reassign_order(order_id, new_salon_id)` (`U-A-05`):
  - Ручное назначение/смена салона администратором с проверкой наличия оборудования и услуг.
- Управление салонами (`U-A-02`: добавление, скрытие, блокировка удаления салона при наличии активных заказов) и сотрудниками (`U-A-03`: создание, назначение роли `MANAGER`/`ADMIN`, привязка к салону, блокировка).
